# Cleaner 1.1.0-beta.1 — отчёт этапа

## Реализовано

- «Что нового?»: текущая версия из сборки, RU/EN, список изменений и исходная версия 1.0.0 без выдуманной даты публичного выпуска.
- История последних 50 анализов и очисток: поиск, отменённые/отклонённые/ошибочные запуски, подробности, экспорт JSON и переход к связанному карантину. Старые записи сохраняются; недостающие сведения обозначаются как отсутствующие.
- Отдельный анализ без очистки: объёмы по операциям и категориям, до 5 примеров файлов на операцию, число остальных файлов, причины пропусков. Системным операциям с неизвестным объёмом не приписывается нулевой ожидаемый результат.
- До 30 пользовательских пресетов очистки. Название обновляет существующий набор без потери идентификатора. Неизвестные операции нельзя сохранить; неудачная запись откатывает изменения пресета в памяти.
- Компактная/просторная плотность списков, адаптивная сводка очистки, сохранение геометрии окна и ограничение окна текущей рабочей областью экрана.
- Пересмотр риска: 16 системных твиков переведены из safe в caution; «Безопасно» заменено на «Низкий риск» без гарантии ускорения. Мягкая очистка содержит только личный Temp и отчёты WER. Из стандартной исключены системные команды и корзина; из глубокой исключён автоматический выбор личных загрузок. Пресеты производительности, игр и разработчика сокращены.
- Удалены неиспользуемые Serilog, XamlFlair.WPF и Microsoft.Xaml.Behaviors.Wpf; их старые транзитивные зависимости больше не нужны приложению.
- Portable Release ZIP Windows x64 со включённым .NET 10 runtime, внешним Data, инструкциями, лицензиями зависимостей и SHA256. Сборщик не запускает приложение и не удаляет предыдущие пакеты.
- Подготовлен GitHub CI: аудит зависимостей, сборка, изолированные тесты, проверки WPF на искусственных данных, ZIP как artifact. Публикация GitHub Release и отправка коммитов не выполнялись.

## Дополнительная ошибка записи

При проверках воспроизвёлся отказ File.Replace с сообщением `Unable to remove the file to be replaced`; ранее один файловый тест оставил перенос карантина pending, а другой — неполное восстановление. Источник внешнего вмешательства в файл не установлен; приписывать его антивирусу оснований нет.

AtomicFile теперь ограниченно повторяет ошибки 32/33/1175: до 5 попыток, суммарные задержки до 600 мс. Обычные запреты доступа не обходятся. При частичных ошибках замены 1176/1177 записанный и сброшенный на диск временный файл сохраняется для восстановления. Семантика этих ошибок описана в [Microsoft ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew). Постоянный отказ по-прежнему останавливает изменение; потеря журнала не маскируется успешным результатом.

## Проверено

- Полный изолированный набор: **409 успешных тестов** (App 28, CLI 31, Core 350), включая 100 последовательных переносов/удалений тестовых каталогов, реальную временную блокировку собственного журнала и модель частичных Win32-ошибок.
- Сборка GUI и инструмента визуальных проверок: 0 ошибок и предупреждений после актуального восстановления зависимостей.
- Аудит NuGet всех проектов и инструмента визуальных проверок с ошибкой при NU1900–NU1904: завершён без предупреждений. Недоступность источника в одном промежуточном запуске была устранена повторным пересчётом восстановления.
- RU/EN: все 9 страниц на искусственных данных, 1120×700 и 1360×860, PNG при 100%/200%; результаты анализа, переключение плотности, навигация настроек и сохранение предпочтений. На минимальном размере видны 4 полные строки очистки, 4 оптимизации и 6 служб.
- Собранный ZIP проверен на целостность, наличие EXE/Data/переводов/версий/лицензий и отсутствие пользовательских настроек, журналов, карантина и записей восстановления.

## Что ещё проверить вручную

- Первый запуск распакованного пакета на другом компьютере, обычный пользователь/UAC, перезапуск и сохранение настроек; этот EXE агентом не запускался.
- Реальные операции Windows, службы, реестр, точки восстановления и фактический откат твиков — в Windows VM со снимком. Готовой VM здесь нет; WindowsIntegration не запускался. Совместимость и полезность твиков пока не подтверждены.
- Настоящий DPI Windows 125/150/200%, несколько мониторов, клавиатура и доступность. Растровая отрисовка при 200% не заменяет запуск приложения при системном DPI.
- Архитектура ARM64: сценарий сборки есть, отдельная сборка и проверка на ARM64 не проводились.
- Перед публичным выпуском: выбранная владельцем лицензия исходников (LICENSE пока отсутствует), отзывы друзей, подпись EXE и проверка GitHub CI после отправки кода.

Честная оценка: приложение стало удобнее и лучше защищает данные восстановления; эта версия подходит для ограниченного beta-тестирования. До статуса проверенной системной утилиты остаются реальные проверки Windows и подтверждение эффекта твиков. Инструкции: RELEASE_GUIDE.md и FRIEND_TESTING.md.

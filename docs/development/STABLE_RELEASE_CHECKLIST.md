# Cleaner: от beta.6 к стабильному выпуску

Beta.6 объединяет программные изменения этапов 1 и 2. Выпуск RC и стабильной версии зависит от результатов ниже, а не от номера beta или количества реализованных функций.

## Release Candidate

- [ ] Зафиксировать функции; новые предложения перенести за пределы RC.
- [ ] Проверить исходники, сборку, аудит зависимостей и изолированные тесты после последнего изменения.
- [ ] Проверить миграцию исходных настроек, старой истории, manifest-only карантина, новых moves.jsonl, незавершённых перемещений/удалений. Старые системные бэкапы без ожидаемого состояния не перезаписывают сторонние настройки.
- [ ] Пройти [матрицу Windows](../testing/COMPATIBILITY.md) в согласованных VM: Windows 10 22H2 x64, Windows 11 24H2/25H2/26H2 x64. Не добавлять build в verifiedWindowsBuilds без протокола конкретного действия.
- [ ] На одноразовых данных проверить отмену, фактическое завершение процесса в середине операции, нехватку места, повреждение журнала, блокировки и подмену файла/каталога после анализа.
- [ ] Сверить содержимое восстановленных файлов; существующие файлы сохраняются, конфликтная копия получает отдельное имя. Права доступа не меняются, приложения не завершаются.
- [ ] Проверить 0–100%, недоступный диск, смену диска, обновление раз в 30 секунд только при видимой странице и после операции. Проверить отсутствие двойного подсчёта, пустую историю, legacy-записи и отдельные объёмы карантина/удаления.
- [ ] Реальный UI: RU/EN, небольшое окно, Windows DPI 100/125/150/200%, клавиатура, экранный диктор, отсутствие ошибок привязки. Рендер PNG в масштабе 2x не заменяет изменение DPI Windows.
- [ ] Проверить автоочистку в согласованной VM: обе временные метки от 24 часов, исключения, полноэкранное активное окно, открытый диалог, другая операция и закрытое приложение.
- [ ] Проверить запуск с Windows, перенос папки приложения и установку новой ZIP-копии. Обновление только по действию пользователя; официальный GitHub Release.
- [ ] Сравнить производительность на одинаковом числе и размере одноразовых файлов, одном диске и одинаковом состоянии кэша. Записать число объектов, суммарный объём, время и условия; не публиковать один замер как гарантированное ускорение.
- [ ] Исправить замечания тестировщиков, не оставлять известные критические ошибки или потерю файлов.

## Подготовка выпуска

1. После прохождения проверки обновить `Directory.Build.props`, добавить запись RU/EN в `Cleaner.Core/Data/releases.json`, сохранить предыдущие версии. Обновить README RU/EN и RELEASE_NOTES.
2. Выполнить проверку кода тестов и `./run-isolated-tests.ps1`; реальные проверки Windows согласовываются отдельно. Выполнить строгий NuGet audit и Release build.
3. Запустить `./build-preview.ps1`. Проверить EXE version, Data, README, лицензии, содержимое ZIP и SHA-256. Не включать профиль, карантин, логи, исходники или внутренние документы в пакет.
4. Зафиксировать точные исходники этой сборки, затем вручную создать pre-release для RC. Публикация и покупка сертификата подписи — отдельные решения владельца проекта.
5. Стабильную версию выпускать только после выполненных критериев. Совместимость отдельных системных действий разблокировать по результатам проверки, а не глобальным включением всех твиков.

Полное отсутствие любых ошибок не обещается. Критерий выпуска — подтверждённые сценарии, понятные ограничения и отсутствие известных критических ошибок.

# Cleaner 1.1.0-beta.7 — выполнено и проверено

Дата: 2026-10-14. Это бета; доступность функций не означает подтверждённую совместимость со всеми версиями Windows.

## Изменения относительно beta.6

- Каталог очистки: все 56 правил включены; 45 доступны в обычном режиме, 11 добавляются в экспертном. Доступность и автоматический выбор разделены.
- Базовый пресет выбирает пользовательский и системный Temp; стандартный добавляет миниатюры и кэш браузеров; глубокий — выбранные кэши приложений. Игровой профиль: Temp и миниатюры. Шейдеры, истории, готовые загрузки, дампы, облачные данные и необратимые команды в пресеты не входят.
- Ручной Temp включает доступные файлы любого возраста и расширения. Предупреждение предлагает закрыть приложения: отсутствие блокировки не доказывает ненужность файла. Автоочистка сохраняет возраст создания/изменения 24 часа, защиту документов и настроек, карантин и ожидание полноэкранного приложения.
- Для ручного Temp сохранены исключения, защита системных деревьев, runtime .NET, ссылок, облачных объектов, занятых и изменившихся файлов. Полный план исключает файлы, появившиеся после анализа. Проверка доступа исправлена: доступ только к атрибутам обходил некоторые блокировки; теперь запрашивается чтение без чтения содержимого. [Описание CreateFile и sharing у Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew).
- 62 твика: 27 доступны в обычном режиме по ограничениям Windows build, 35 — в экспертном. Непроверенные твики доступны с отметкой «Не проверено». Минимальный/максимальный build по метаданным и защита критических служб сохраняются. Неприменимая настройка может игнорироваться конкретной редакцией Windows; это ещё требует VM-проверки.
- Пресеты оптимизации содержат явные списки и не выбирают службы, антивирус, параметры сети и обновлений. Профиль для игроков не отключает запись игр автоматически.
- Системные команды включены в подтверждённый план. Истории реестра сверяются с состоянием на момент анализа; новые значения блокируют применение устаревшего плана. Неизвестный эффект штатной команды не записывается как освобождённое место.
- Твики служб сохраняют тип запуска, включая отложенный старт. Не выполняют принудительную остановку; полный эффект после перезагрузки. Откат проверяет ожидаемое состояние и сохраняет сторонние изменения. Неполные старые бэкапы остаются для ручной проверки.
- Управление некритическими службами и удаление старых теневых копий доступны в экспертном режиме с подтверждением. Критические службы защищены в обоих режимах.
- Windows.old обслуживается штатным `cleanmgr /AUTOCLEAN`, Store — `wsreset` без установки магазина. Windows Update выбирает только Download, не останавливает службы и не удаляет DataStore. DISM не использует `/ResetBase`. Теневые копии ограничены системным томом; самая новая сохраняется.
- Миниатюры, шрифты и история активности используют файловый план; без принудительного завершения Explorer или остановки служб. OneDrive выбирает старые журналы, Spotify — онлайн-кэш без офлайн-хранилища, загрузки — незавершённые временные файлы от 30 дней. CBS/Windows Logs выбирают старые журналы от 7 дней, сохраняют активный CBS.log.
- Настройки → «Данные Cleaner и место на диске»: анализ и подтверждение удаления журналов прошлых дней. Сверяется идентичность файлов; новые/изменившиеся и текущий журнал, настройки, карантин и данные восстановления сохраняются.
- Предупреждения RU/EN объясняют повторное создание кэшей, место, занятое точками восстановления и карантином, а также журналы штатного обслуживания Windows. Сохранена история предыдущих версий; обновлены README RU/EN, описание выпуска и чек-лист тестировщика.

- Debug и Release: `dotnet build Cleaner.slnx --no-restore --nologo -m:1` (Release с `-c Release`), 0 ошибок и 0 предупреждений.
- Финальный изолированный запуск: **508/508 успешно**, пропусков 0: App 67, CLI 32, Core 409. `WindowsIntegration` исключён. Реальные службы, системные команды и реестр заменены заглушками; файловые проверки используют собственные временные данные.
- TRX: `.test-sandbox/50f4fd6f32da484888a1123799b29d20/results`. Первый запуск в ограниченной песочнице прервался из-за отсутствия связи с testhost; повтор выполнен с разрешённым запуском процесса и сохранённой файловой изоляцией. Промежуточный запуск выявил два падения проверки заблокированных Temp-файлов; они исправлены, финальный полный набор прошёл.
- Дополнительные проверки beta.7: доступность режимов без выполнения операций; пресеты без опасных автоматических выборов; свежие Temp-файлы произвольных расширений; блокировки; новый файл после анализа; неизменность защиты автоочистки; шаблоны/возраст журналов; команды только через заглушку; изменение режима и отмена; изменившаяся история реестра; откат служб с конфликтом; защита критических служб; сохранение новых/изменившихся журналов Cleaner; явный флаг CLI `--expert` без автоматического исполнения.
- WPF RU/EN: все страницы, небольшое окно, рендеры 1x/2x, состояния графиков, пустая история и поиск восстановления; ошибок привязки 0. Проверены первый запуск, язык, версия, вторичная навигация, диагностический предпросмотр и настройки с заглушкой автозапуска. Эти проверки не запускают Cleaner startup, реальные таймеры и системные действия.
- RU-рендеры: `.test-sandbox/visual-419b79b5c28e4e148da9f43cb689da5f`; EN: `.test-sandbox/visual-49622f63871a4f8faf78b0a769e70d37`. Это изолированные примеры данных интерфейса, не сведения реального компьютера. Реальный DPI Windows 100–200% и доступность с клавиатуры требуют отдельного испытания.
- Сравнение журналирования в финальном изолированном наборе: 100 файлов — полная перезапись 4216 мс, последовательный журнал 775 мс; 300 файлов — 9261 и 1120 мс. Это небольшой искусственный набор на одном диске с фоновой нагрузкой, не гарантия скорости и не испытание 3000 реальных файлов.
- Зависимости не добавлялись. Проверка NuGet внутри ограниченной песочницы сообщила NU1900 из-за недоступности сети. Отдельный полный аудит всех зависимостей выполнен с доступом к официальному NuGet: `dotnet restore Cleaner.slnx -p:NuGetAudit=true -p:NuGetAuditMode=all '-warnaserror:NU1900,NU1901,NU1902,NU1903,NU1904'`, exit 0, предупреждений нет. Это результат источника аудита на момент проверки, а не гарантия отсутствия будущих уязвимостей.

## Что проверить вручную до публичного выпуска

1. Снимок подготовленной Windows VM, одноразовый профиль и разрешение владельца. Реальные Temp, настройки и карантин пользователя в этом этапе не очищались; Windows-команды, службы и автозапуск не изменялись.
2. [Матрица Windows и каталог ограничений](../testing/COMPATIBILITY.md): все целевые системы ещё требуют реальных испытаний. Проверить фактический эффект твиков и откат, включая изменение исходного состояния другой программой.
3. В VM проверить ручной Temp и предупреждение, сохранность исключений/runtime, карантин и восстановление, конфликты имени без перезаписи, отмену, ошибки прав доступа, заполнение диска, перезапуск после прерывания и старые журналы.
4. Проверить штатные команды, реальные журналы Windows, откат старой Windows/теневых копий и последствия гибернации. Такие команды не поддерживают карантин; отмена не означает откат уже выполненной части. Не проверять это на основном компьютере.
5. Проверить обновление с beta.6 и более старых версий, RU/EN, небольшое окно, реальные DPI 100–200%, Tab/Shift+Tab/Enter/Esc и понятность предупреждений.
6. Подтвердить скорость удаления большого одноразового карантина и стабильность автоочистки. Карантин на том же диске продолжает занимать место; перенос между дисками пропускается.
7. Пройти [чек-лист тестировщика](../testing/FRIEND_TESTING.md), затем собрать отзывы. Для стабильного выпуска остаются критерии [STABLE_RELEASE_CHECKLIST.md](STABLE_RELEASE_CHECKLIST.md), включая испытания минимум с пятью неопытными пользователями.

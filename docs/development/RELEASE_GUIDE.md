# Сборка EXE и передача друзьям

## Готовый способ

Установите .NET 10 SDK либо Visual Studio с компонентами разработки классических приложений .NET. Откройте PowerShell в корне репозитория:

```powershell
dotnet restore Cleaner.slnx
dotnet build Cleaner.slnx --no-restore --nologo -m:1
powershell -NoProfile -File .\run-isolated-tests.ps1 -NoBuild
powershell -NoProfile -File .\build-preview.ps1
```

Тесты изолированы; WindowsIntegration исключён. Сборщик **не запускает Cleaner**, очистку, системные команды или изменение настроек Windows. Он скачивает зависимости NuGet, создаёт новую папку в `artifacts\preview`, собирает Release, проверяет обязательные файлы и формирует ZIP + `.sha256`. Предыдущие пакеты не удаляются и не перезаписываются.

Передайте друзьям **ZIP целиком** и SHA256. Внутри: `Cleaner.App.exe`, папка `Data` и инструкции. Распаковать надо всё. Одного EXE недостаточно, поскольку каталоги операций, переводов и версий остаются внешними файлами.

Пакет выпускается только для Windows x64 со включённым .NET runtime. ARM64 и Insider вне первого стабильного выпуска. Успешная компиляция не подтверждает совместимость системных действий.

Проверка архива:

```powershell
Get-FileHash -LiteralPath 'ПОЛНЫЙ_ПУТЬ_К_АРХИВУ.zip' -Algorithm SHA256
```

SHA256 подтверждает совпадение файла с переданным автором архивом, а не безопасность программы. EXE пока не подписан.

## Сборка вручную без сценария

```powershell
dotnet publish Cleaner.App\Cleaner.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:PublishTrimmed=false -o artifacts\manual-preview
```

Используйте новую папку назначения для каждого выпуска. WPF не обрезается (trimming выключен). Native библиотеки single-file сборки извлекаются .NET при запуске в собственный каталог runtime; это штатный механизм, описанный в [документации Microsoft](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview). [Self-contained deployment](https://learn.microsoft.com/en-us/dotnet/core/deploying/) включает .NET, поэтому пакет больше framework-dependent сборки.

## История версий

Версия задаётся в `Directory.Build.props`. Для следующей сборки меняйте `Version` и `FileVersion`; `AssemblyVersion` меняйте при изменении базовой версии приложения, затем добавляйте запись в начало `Cleaner.Core\Data\releases.json` с RU/EN, датой и фактическими изменениями. Тест проверяет наличие текущей версии. Не меняйте задним числом описание уже переданного пакета; после beta.7.1 выпускайте новую beta, например `1.1.0-beta.8`. Версия `1.0.0` в истории обозначает исходный проект без подтверждённой даты публичного выпуска. Критерии RC и стабильного релиза — в [чек-листе](STABLE_RELEASE_CHECKLIST.md).

## Перед публикацией

1. Пройдите `FRIEND_TESTING.md`, отдельно — Windows VM со снимком. Подтвердите применяемые настройки, откат, доступ и отмену; интерфейсные тесты этого не заменяют.
2. Аудит NuGet: `dotnet restore Cleaner.slnx -p:NuGetAudit=true -p:NuGetAuditMode=all`. Если источник аудита недоступен, проверка не выполнена. CI блокирует предупреждения NU1900–NU1904.
3. Выберите лицензию для исходников: сейчас файла LICENSE нет. Сборщик уже включает метаданные и доступные лицензии пакетов NuGet и runtime в THIRD_PARTY_NOTICES.md и Licenses; проверьте их перед публичным распространением. Не приписывайте себе права на библиотеки.
4. Отправьте beta друзьям, соберите воспроизводимые ошибки. После исправлений и проверки выпустите новый пакет.
5. Проверьте, что в Git не попадают `.test-sandbox`, `.recovery`, пользовательские журналы, карантин, резервные копии и секреты. `artifacts` игнорируется; ZIP можно приложить к отдельному GitHub Release вручную.
6. По возможности подпишите будущий публичный EXE своим сертификатом. Не используйте автоматическое обновление без проверки подписи и целостности.

GitHub workflow `.github/workflows/verify.yml` подготовлен: восстановление и аудит зависимостей, сборка, изолированные тесты, проверки привязок на искусственных данных и ZIP как artifact. Он сработает после отправки репозитория на GitHub. Этот локальный этап ничего не публикует.

Пользовательские инструкции: README.md (English), README.ru.md (русский). В пакет включены оба файла. Порядок публикации beta и черновик текста релиза: PUBLISHING.md и RELEASE_NOTES.md. В первом запуске нет автоматического UAC-запроса: создание точки предлагается в памятке и запускается только по выбранному действию.
